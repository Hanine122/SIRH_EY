# SSIS Package — staging.stg_collaborateurs → dwh.dim_collaborateur

## 1. Connection Managers
- `CM_SIRH` — OLE DB connection to the SQL Server instance/database hosting both `staging` and `dwh` schemas (single connection, since both schemas live in the same DB).

## 2. Control Flow
- One **Data Flow Task**: `DFT_Load_DimCollaborateur`.

## 3. Data Flow
1. **OLE DB Source** — `SRC_stg_collaborateurs`
   - Connection: `CM_SIRH`
   - Data access mode: `Table or view` → `staging.stg_collaborateurs`
   (or `SQL command` if you need to filter/dedupe before load, e.g. exclude rows already in `dim_collaborateur` by `collaborateur_id`).

2. *(Optional but recommended)* **Lookup** — `LKP_Existing_Collaborateur`
   - Reference: `dwh.dim_collaborateur`, match on `collaborateur_id`.
   - No match → insert (new dimension row). Match → redirect to a separate branch if you later want SCD/update handling (out of scope for a straight initial load).

3. **OLE DB Destination** — `DEST_dim_collaborateur`
   - Connection: `CM_SIRH`
   - Data access mode: `Table or view - fast load`
   - Table: `dwh.dim_collaborateur`
   - **Keep Identity: UNCHECKED** — `collab_key` is a surrogate `IDENTITY` column generated by SQL Server on insert; SSIS must never supply it.

## 4. Column Mapping (Source → Destination)

| Source (staging.stg_collaborateurs) | Destination (dwh.dim_collaborateur) |
|---|---|
| `collaborateur_id` | `collaborateur_id` |
| `nom` | `nom` |
| `prenom` | `prenom` |
| `email` | `email` |
| `grade` | `grade` |
| `departement` | `departement` |
| `date_embauche` | `date_embauche` |
| *(not mapped — leave blank)* | `collab_key` |

`collab_key` must not appear in the mapping at all — SSIS auto-excludes IDENTITY columns from the destination's available input list when "Keep Identity" is off, so as long as it stays unchecked there's nothing further to configure.

## 5. IDENTITY handling summary
- `collab_key` (dim side): auto-generated, never mapped, "Keep Identity" off.
- `collaborateur_id` (business/staging side): plain `INT`, no IDENTITY — flows through as a regular natural-key column used for the lookup/join back from `dwh.fact_evaluations`.

## 6. Load order
Run this package before any package/task that loads `dwh.fact_evaluations`, since the fact table's FK (`collab_key`) requires the matching dimension row to already exist.
